# 0017: Verified adoption capture

Status: accepted direction; executable acceptance is recorded separately.

## Context

Private Claude guidance and skill-upgrade backups entered audit copies. Debt collection
also included excluded vendor baselines, and parity independently captured live sources.
These inconsistencies weaken both privacy and the meaning of resolved-debt evidence.

## Decision

Use one input eligibility policy for adoption debt and audit capture. Keep ordinary receipts,
exclude private upgrade backups, and derive accepted debt plus independent analyzer copies
from one verified pristine capture. Check destination bytes, detected source changes and
policy-bound fingerprints. Regenerate old parity evidence; keep schema 1 and Packwerk authority.

## Consequences

Extra copying/hashing costs storage and time. Temporary directories are private and normally
cleaned, but this is neither atomic filesystem capture nor a sandbox for application boot.
External bundle inputs, services and hostile mutation remain outside that guarantee. Source
baselines, dependencies and application behavior remain untouched. No new CLI or runtime exists.
