# 0008: Fresh setup and guided adoption

Status: accepted, local unpublished delivery.

Foundry should make a fresh Rails app usable while preserving its selected stack. The installed gem therefore owns a local application template and a setup generator that composes existing foundation and skill installers. Setup opts into loading in the application class before Rails builds load paths; ordinary installation keeps its disabled default. An empty manifest leaves business ownership decisions with developers.

Existing applications need gradual extraction, not automatic rewrites. Assessment reuses the established source roots, parser, constant resolver, and Packwerk dependency/privacy rules without initializing Rails. Namespace and directory clusters are review candidates only. Developers preserve tables with explicit mappings, move behavior manually, introduce public APIs, and test runtime behavior.

A separate versioned baseline records exact reviewed boundary identities and occurrence counts. It requires rationales and rejects wildcard or structural exemptions. Reduced or resolved debt requires explicit cleanup, so old acceptance cannot silently return. This gate never feeds strict checks or permits Packwerk TODO bypasses. Its success reports no unaccepted boundary debt, not completed adoption.

This intentionally adapts the research's incremental adoption guidance to Foundry's existing four profiles and strict checker. Dynamic Ruby, ownership judgment, rationale quality, and behavioral correctness remain human/runtime responsibilities. Automatic extraction, schema migration, broader profiles, example expansion, and publication require separate decisions.
