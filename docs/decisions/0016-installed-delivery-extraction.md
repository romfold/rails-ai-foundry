# 0016: Installed guidance for existing delivery extraction

Status: Accepted

## Context

The Campfire adoption showed that moving Ruby files alone is insufficient. Routes,
helpers, views, JavaScript pins, asset paths and test discovery have separate wiring.
Its frozen framework limitations also show why loading and browser evidence must not
be represented as completion of blocked native tests.

## Decision

Ship a staged, executable guide within the existing adoption, package, refactoring and
verification skills. Characterize an ordinary shell feature before moving delivery into
an upstream pack. Preserve models, tables, identifiers, authentication, shared UI and
locked dependencies. Use packs for package creation, packs-rails for Rails paths and
Packwerk for boundaries. Asset wiring stays explicit and application-owned.

Replay the installed guide in disposable applications with both package roots. Require
real HTTP/browser acceptance before and after extraction, targeted faulty controls and
healthy recovery. A separate contributor bundle freezes the demonstrated combination;
it does not authorize changing a consumer's dependencies. Test reviewed upgrades across
all three targets while preserving application customizations and selected workflows.

## Consequences

The guide adds no runtime, automatic extraction command, loader, configuration key or
catalog application. Different asset pipelines still need application-specific wiring.
A route's controller string does not require making private delivery a public business
API. Existing blocked application tests remain explicitly unfinished. Reproducible
installed acceptance is evidence of this fixture, not a universal compatibility claim.
