## Why

Rails AI Foundry needs a reproducible development entry point before framework implementation begins. Contributors need to distinguish working capabilities from research ideas and use one English, spec-driven workflow across humans and coding agents.

## What Changes

- Establish local, pinned OpenSpec tooling and shared agent skills.
- Document project purpose, architecture direction, contribution rules, and a staged roadmap in English.
- Provide a repeatable specification validation command and document Conventional Commits without automated enforcement.
- Record the completed foundation as baseline behavior while future runtime capabilities remain proposed.

## Capabilities

### New Capabilities

- `contributor-workflow`: Reproducible tooling, discoverable guidance, English project content, explicit change lifecycle, and documented commit conventions.

### Modified Capabilities

None. The repository has no existing behavioral specifications.

## Impact

Affects repository tooling, documentation, shared agent guidance, and OpenSpec artifacts. Adds OpenSpec as a local development dependency. Introduces no Rails application, Ruby gem implementation, runtime API, deployment, license selection, or commit hooks.
