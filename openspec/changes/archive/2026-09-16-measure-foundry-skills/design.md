## Context

The composition and adoption applications supply concrete failure modes. Existing runtime microbenchmarks do not evaluate coding-agent outcomes. This contributor surface must preserve production dependencies, eight skills, twelve examples and the current CLI.

## Goals / Non-Goals

Provide six reproducible tasks, controls, isolated execution and the exact authorized pilot. Do not implement an agent runtime, production service, extra trials, paid provider calls or a productivity claim.

## Decisions

- Use a small real Rails knowledge application with SQLite for offline task execution. Model provider and search transports are deterministic application doubles; concurrency/revision behavior is exercised explicitly. The independently verified composition recipe remains the real-service evidence.
- Materialize immutable versioned task inputs and three groups. Business APIs and requirements are identical; plain Rails omits package checks, the packs group uses upstream checks, and Foundry adds its actual packaged guidance/checks. Workflow is none in every group.
- Keep preparation, grading, reporting and pilot execution outside the Foundry CLI. Freeze dependency locks, task requirements, tests, reference/faulty transformations and tool versions before measurement.
- Run Linux containers using pinned cached Ruby and verified official Codex release assets. Mount only one candidate and its permitted runtime during a trial. Never mount the repository, evaluator, controls or other candidates. Grade a final copy in a fresh network-disabled container after stopping the agent.
- Give all groups the same prompt template, model/reasoning, resource/network policies and budgets. Record group-specific architecture instructions as treatment inputs. Serialize all eighteen attempts; stop on auth/quota failure and retain unstarted outcomes.
- Capture JSONL events, final diffs and external test results. Preserve missing usage as null. Do not infer money from token counts under ChatGPT access.

## Risks / Trade-offs

Small tasks do not represent an entire product or independent user study. Offline doubles do not establish live-provider quality or Elasticsearch correctness. Container isolation and grader controls must pass before measuring. Host Docker capacity and model availability can prevent the pilot; report actual failures rather than reducing the experiment silently.
