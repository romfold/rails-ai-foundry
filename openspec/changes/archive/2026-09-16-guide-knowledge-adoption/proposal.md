## Why

The advanced application proves composition but does not show a safe path from an existing
Rails application. Current adoption inventory is read-only, but its next steps are generic;
refactoring currently shares Foundry-reference diagnostics without the architecture rules
already used by source checking.

## What Changes

- Add an executable knowledge adoption journey with independently verified checkpoints:
  characterization, assessment, AR-preserving extraction, public caller repair, explicit ROM
  persistence change, and later integration features.
- Make adoption recommendations specific to discovered package roots, configured contexts
  and workflow initialization. Reuse selected-context architecture diagnostics in refactoring.
- Strengthen existing adoption, planning, refactoring and verification skills with checkpoint,
  rollback and evidence guidance. Keep all eight skill identities and existing CLI contracts.
- Replay against an installed gem in disposable copies, including custom roots and workflow history.

## Capabilities

### New Capabilities

- `knowledge-adoption`: Executable incremental application-specific adoption checkpoints.

### Modified Capabilities

- `adoption-evidence`: Context-specific read-only recommendations.
- `architecture-planning`: Include current architecture rules in selected-context evidence.
- `foundry-skills`: Checkpoint, rollback and characterization guidance in existing skills.

## Impact

Existing Assessment/Refactor implementations and targeted tests; four existing product skills;
contributor-only adoption fixture/replay; documentation and independent offline CI. No new
CLI command, schema change, automatic extraction, persistence migration facility or runtime.
