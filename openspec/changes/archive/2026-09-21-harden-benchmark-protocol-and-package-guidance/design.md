## Context

See proposal.md and the immutable repeatability study at revision b405289. Package checking succeeds when privacy is disabled, because no privacy policy is then enforced. The candidate instructions prohibit changing visible tests but also request new tests without an explicit example of allowed placement. Preflight currently conflates completed protocol rejection with missing verification.

## Goals / Non-Goals

Provide actionable package guidance, unambiguous contributor protocol instructions and safe continuation of independent trials. Do not relax protected-file checks, alter upstream requirements, inject repair answers into agents or claim repaired candidates are improved model scores.

## Decisions

- Keep Packwerk authoritative. Existing generic packs/verification guidance will show explicit enforcement fields and a disposable intentional private access check. No new Foundry schema or checker policy is needed.
- All three Foundry groups receive the same protected-file instructions and a neutral example of a new test filename. Product guidance refers generically to application-owned/protected tests.
- Future preflight may continue after invalid protocol only when independent verification records actual protected paths and a completed task-phase grade, the native outcome is completed, evidence is intact and accounting is known. Grader disagreement, infrastructure errors, missing evidence and failed smoke still stop. Preserve invalid credit; do not bypass old frozen studies.
- Repair only the privacy setting in the boundary candidate; relocate added tests in the embedding candidate to an unprotected new test class. Store incremental/full patches and hashes separately. Use existing verifier against all seven saved candidates, repaired copies where needed, plus three pinned upstream references. Reference results demonstrate harness correctness, not agent performance.
- New live runs require explicit budget authorization and a new frozen study. Keep offline acceptance separate from paid results; no automatic retry loop.

## Risks / Trade-offs

- Stronger wording cannot guarantee agent compliance. Verify with tests and report actual outcomes.
- Allowing invalid predecessors could conceal infrastructure problems. Require completed independent task evidence and native outcome, and retain all cost/provenance guards.
- Frozen tasks change when instructions/skills change. Record new hashes and distinguish the experiment from the earlier repeatability study.

## Migration Plan

Land tested guidance and contributor changes, record offline acceptance, then freeze new inputs. Old study/tool hashes and evidence remain unchanged; old workspaces must not resume with the new implementation.
