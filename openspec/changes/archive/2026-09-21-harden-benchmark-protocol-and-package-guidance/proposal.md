## Why

The latest frozen study exposed a missing package privacy setting and a correct behavioral repair submitted with a protected test edit. Its invalid attempt also prevented unrelated tasks from running. Address those reusable gaps without changing historical scores or weakening acceptance.

## What Changes

- Make package privacy verification explicit in existing product guidance, including an intentional private-access control.
- Clarify protected versus new test files equally for all Foundry comparison groups; keep task requirements and upstream tasks unchanged.
- Permit a future study to continue after a fully verified isolated protocol violation with known accounting, retaining invalid status. Keep missing evidence, grader disagreement, authentication/accounting errors and failed smoke as stops.
- Preserve separate offline repairs for both latest candidates and execute ten offline task checks, using unchanged upstream references for the unstarted tasks. Retain failing controls.
- Prepare a new frozen live study only after acceptance and separate paid authorization; never retry until a desired score appears.
