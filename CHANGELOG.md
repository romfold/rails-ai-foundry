# Changelog

## Unreleased

### 1.0.0 local release candidate

No release has been published. The gem version is `1.0.0`; candidate identity is the
committed source plus the built archive checksum, not a registry release or Git tag.

- Development-time conventions and eight skills built on Rails, packs, packs-rails and
  Packwerk. Application execution belongs to Rails and upstream libraries.
- Independent profiles, event/CQRS patterns, capabilities and optional specification
  workflows; current configuration/report schema 1 and preserving generators.
- Reviewed skill upgrades with content-bound previews, explicit conflict decisions,
  recovery and conditional rollback for application-owned customizations.
- Installed Minitest and opt-in RSpec feature verification, package-aware baseline
  discovery, and separate HTTP/browser evidence. Applications own verification commands.
- Package-aware source, prompt and refactoring assessment, including upstream packages
  without Foundry intent and independently owned nested packages.
- Verified audit capture excludes private Claude metadata and skill-upgrade backups,
  aligns debt inventory with analysis inputs, and gives Packwerk/pks independent copies
  of the same captured input. Old parity evidence must be regenerated, including when
  the gem version is unchanged. Source baselines are never silently accepted or rewritten.
- Explicit packaged-resource inventory, privacy checks and executable installed journeys.
  Twelve independently bundled applications and advanced recipes remain repository-only.

Ruby >= 3.3 and railties >= 7.1 floors are unchanged. No existing dependency versions or
locks are upgraded for this candidate. See [stable contracts](docs/stable-contracts.md),
[setup](docs/setup.md), [skill upgrades](docs/skill-upgrades.md) and
[audit input changes](docs/adoption.md#verified-audit-inputs).

Hosted CI is deliberately not run for this preparation; local acceptance is not hosted
Linux evidence. Campfire's native-test limitation and unfinished guidance studies remain
separate limitations. Offline checks do not establish live-provider quality or productivity.
Publication and destination configuration remain separate from candidate preparation.
